## 一、两条技术路径的根本差异

```
                        OEM/合作路径                           玩家路径
                        ────────────                          ──────────
 数据源         hook 游戏服务器内部 API               只通过客户端接收的信息
 公告类型       结构化状态对象 (MapId, MobList...)       屏幕文字 + 小地图红点
 怪物信息       直接读 MonsterDefinition                击杀后积累认知
 地图信息       直接读 GameMapDefinition                走过才认识
 经验来源       游戏配置本身就是完整知识                需要 AI 自行探索总结
 决策依据       规则表 + 已知数据                       经验库 + 规则表
```

如果 AI 系统是**卖给玩家**的第三方工具，那就**没有内部 API 可用**。AI 角色进入游戏时就像一个新玩家——什么都不知道，需要像人一样"玩久了就懂了"。

这决定了：**AI 系统必须有一个经验积累和群体学习的闭环**，否则就只是一个机械执行指令的外挂。

## 二、核心原则：经验 = 未成熟的规则

**经验和规则不是两套东西，而是同一条"成熟度光谱"上的不同阶段。**

```
规则成熟度光谱:
  ──── 原始日志 ─→ 聚合统计 ─→ 规则候选 ─→ 规则(自动/确认) ─→ 标准规则
      0%                                             60%+          100%
      (不可直接执行)                          (可直接执行)     (写入规则表)
```

**核心约束:**

1. **每条经验的终点必须是 `RuleDef`** — 如果一条经验不能最终表达为 `RuleDef { Condition, ScriptId, Parameters }`，它就是无用的。经验系统的唯一产出就是规则。

2. **SQL 思维** — 经验 = `SELECT event_type, map, monster, AVG(outcome) FROM action_logs GROUP BY event_type, map, monster HAVING COUNT(*) >= N`。聚合的结果直接就是一条规则的条件和参数。

3. **置信度是经验和规则之间的唯一界限** — 置信度低的叫"经验"（不直接使用），置信度高的叫"规则"（直接进规则引擎）。两者没有结构差异。

```
规则表 rules_default.json:
  { ruleId: "hunt_golden_at_lv80",   condition: "golden_monster_alert + level_ge:80",  confidence: 0.95,  autoGenerated: true }
  { ruleId: "hunt_golden_at_lv50",   condition: "golden_monster_alert + level_ge:50",  confidence: 0.35,  autoGenerated: true, disabled: true }
  ↑ 第1条置信度高，自动生效；第2条置信度低，暂不启用（等更多样本）
```

4. **OEM 模式的配置本身就是 100% 置信度的经验** — 从 `MonsterDefinition` 读到的怪物等级、从 `DropItemGroups` 读到的掉落，是系统给的确凿知识。玩家模式需要通过大量日志才能达到同样的认知。

## 三、经验体系的演变：从行为日志到可执行规则

```
step 1: AI 执行一次行为
  → 产生一条 ActionLog（原始日志）
  → 直接就是一条 "规则候选 v0.1"（置信度≈0，但结构已经是规则格式了）

step 2: 同类型日志累积 > N 条
  → 聚合为 AggregatedExperience
  → 产出 "规则候选 v0.5"（置信度随样本量上升）

step 3: 置信度 > 阈值（如 0.6）
  → 规则候选写入 rules_experience.json
  → 规则引擎下次心跳即可使用这条规则

step 4: 置信度 > 高阈值（如 0.9）或人工确认
  → 规则从 rules_experience.json 提升到 rules_default.json
  → 变成系统级规则，所有 AI 受益
```

### 关键：ActionLog 本身就是规则原料

```
ActionLog 的一条记录:
{
  Trigger: SystemAnnouncement,
  TriggerMessage: "[Lorencia] Golden Invasion!",
  MatchedRuleId: null,           ← 没有规则匹配（第一次遇到）
  Result: Completed,
  MonstersKilled: 15,
  ItemsDropped: [{ "祝福宝石", count: 1 }],
  GoldEarned: 50000,
  DeathCount: 0,
  DurationSeconds: 300,
  WorthRepeating: true
}
↓ 聚合 30 条同类型日志
↓
规则候选:
{
  ruleId: "exp_hunt_golden_lorencia",
  condition: "golden_monster_alert + map_id:0",
  scriptId: "survival",
  minLevel: 40,         ← 统计发现 40+ 存活率 90%
  parameters: { targetMonster: "79" },
  priority: 35,
  description: "[经验生成] 黄金龙在Lorencia刷新→40级+可去",
  autoGenerated: true,
  confidence: 0.82
}
```

## 三、单个 AI 角色的经验日志

### 3.1 行为日志 (ActionLog)

每次 AI 角色执行一个任务（响应公告、去打 BOSS、去合成），记录一条完整的行为日志。

```csharp
/// <summary>
/// 一次AI行为的完整日志。每个 MissionItem 执行后生成一条。
/// </summary>
record ActionLog
{
    // ── 上下文 ──
    string LogId;                  // 唯一ID
    DateTime Timestamp;            // 开始时间
    string AiRoleName;             // 哪个AI角色
    int AiLevel;                   // 当时等级
    string AiClass;                // 当时职业

    // ── 起因：什么触发了这次行为 ──
    TriggerSource Trigger;         // SystemAnnouncement / RuleMatch / UserCommand / Timer
    string? TriggerMessage;        // 原始公告文本（如果是公告触发）
    MiniGameType? TriggerEventType;// 事件类型（如果是事件触发）
    ushort? TriggerMapId;          // 公告中提到的地图（如果有）

    // ── 决策：AI 当时怎么想的 ──
    string? MatchedRuleId;         // 匹配了哪条规则
    string MissionModule;          // 哪个模块执行
    string MissionId;              // 看板任务ID
    string MissionTitle;           // 任务标题

    // ── 执行：做了什么 ──
    string ActionMap;              // 实际去了哪个地图
    short? TargetMonsterNumber;    // 目标怪物编号（如果有）
    int? TargetMonsterLevel;       // 目标怪物等级
    bool ReachedTarget;            // 是否到达目标地点

    // ── 结果：发生了什么 ──
    BehaviorResult Result;         // Completed / Failed / Interrupted / NoTarget
    int? MonstersKilled;           // 杀了多少只
    List<ItemDrop>? ItemsDropped;  // 掉落了什么物品
    int? GoldEarned;               // 捡了多少金币
    int DurationSeconds;           // 耗时
    int? DeathCount;               // 死了几次
    string? FailureReason;         // 失败原因
    
    // ── 事后判断 ──
    bool WorthRepeating;           // 值得再去吗？
    string? Summary;               // AI 自己写的简短短评（预留）
}
```

### 3.2 物品掉落记录 (ItemDrop)

```csharp
record ItemDrop
{
    short ItemGroup;               // 物品组
    short ItemNumber;              // 物品编号
    string ItemName;               // 物品名字
    byte ItemLevel;                // 物品等级
    int DropCount;                 // 掉落数量
}
```

### 3.3 个人经验存储

每个 AI 角色的 `AiPlayer` 持有自己的经验库：

```
aiplayer_data/<roleName>/action_logs.json     ── 行为日志（追加写）
aiplayer_data/<roleName>/experience.json      ── 个人经验总结（定期更新）
```

## 四、群体经验聚合

### 4.1 同步机制

```
每个AI角色                  AI群体经验库
──────────                 ────────────
  ActionLog  ──每日/每小时──→   ActionLogStore
                                ↓
                              按维度聚合
                                ↓
                              AggregatedExperience
                                ↓
                              触发AI分析
```

### 4.2 聚合数据结构

```csharp
/// <summary>
/// 按(事件类型+地图+怪物)聚合的经验统计。
/// </summary>
record AggregatedExperience
{
    // ── 维度 ──
    string DimensionKey;           // "golden_invasion:Lorencia:#43"
    string EventType;              // "golden_invasion" / "mini_game" / "boss_hunt"
    ushort MapId;                  // 地图编号
    short MonsterNumber;           // 怪物编号
    string MonsterName;            // 怪物名字
    int MonsterLevel;              // 怪物等级

    // ── 统计数据 ──
    int TotalAttempts;             // AI 总共去过多少次
    int SuccessCount;              // 成功次数
    int FailCount;                 // 失败次数
    int TotalDeaths;               // 总死亡次数
    int TotalDuration;             // 总耗时（秒）

    // ── 掉落统计 ──
    Dictionary<string, int> DropRates;      // 物品掉落频率
    int AverageGoldEarned;                  // 平均金币收益
    int TotalMonstersKilled;                // 总击杀数

    // ── 等级分布 ──
    int MinPlayerLevel;            // 参与的最低等级
    int MaxPlayerLevel;            // 参与的最高等级
    int AvgPlayerLevel;            // 平均等级

    // ── 时间分布 ──
    int[] HourDistribution;        // 24小时分布，用于发现高峰期

    // ── 综合评分 ──
    float WorthScore;              // 综合性价比评分（0~100）
    string? RecommendedLevel;      // "建议等级80以上"

    // ── 元数据 ──
    DateTime LastUpdated;          // 最后更新时间
    int SampleCount;               // 样本数量
}
```

### 4.3 聚合计算逻辑

```csharp
class ExperienceAggregator
{
    /// <summary>从一批 ActionLog 汇总出聚合经验</summary>
    AggregatedExperience Aggregate(IEnumerable<ActionLog> logs, string dimensionKey);
    
    /// <summary>定期执行聚合（每1小时）</summary>
    Task AggregateAsync();
    
    /// <summary>触发 AI 分析：聚合经验→规则</summary>
    Task<List<RuleCandidate>> AnalyzeForRulesAsync();
}
```

## 五、经验→规则的闭环

这是核心：**从群体经验中自动提炼规则**。

### 5.1 触发时机

- **定时触发**: 每 24 小时检查一次
- **阈值触发**: 某个事件积累了 N 条记录（如 `TotalAttempts >= 30`）
- **手动触发**: 运营人员（或用户）触发

### 5.2 规则候选生成 (RuleCandidate)

本地 AI 分析聚合经验，产出规则候选：

```csharp
/// <summary>
/// 一条待评估的规则候选。由本地 AI 从聚合经验中提炼。
/// </summary>
record RuleCandidate
{
    string ProposedRuleId;              // 建议的规则ID
    string Description;                 // 规则说明
    string Condition;                   // 条件表达式
    string ScriptId;                    // 建议的脚本ID
    int SuggestedPriority;              // 建议优先级
    int MinLevel;                       // 建议最低等级
    int MaxLevel;                       // 建议最高等级
    
    // ── 置信度 ──
    float Confidence;                   // 0~1, 基于样本量
    int SampleSize;                     // 样本数量
    string EvidenceSummary;             // AI 分析摘要
    
    // ── 例子：AI 分析出的规则 ──
    // Condition: "level_ge + level_lt + has_item_group"
    // Evidence: "过去30次黄金入侵中，等级80+的玩家25次获得祝福宝石"
}
```

### 5.3 规则评审流程

```
聚合经验 (100+条黄金怪日志)
  ↓
本地 AI 分析
  ↓ "发现：等级80+去打黄金龙，掉落祝福宝石的概率约25%"
规则候选:
  {
    ruleId: "hunt_golden_at_80",
    condition: "level_ge:80 + golden_monster_alert",
    priority: 35,
    confidence: 0.85,
    evidence: "共87次记录, 22次掉宝, 其中18次等级≥80"
  }
  ↓
人工/自动确认（如果 confidence > 0.9 自动写入）
  ↓
写入 rules_default.json → 所有 AI 下次心跳即可用
```

### 5.4 规则生成的 3 种模式

| 模式 | 条件 | 例子 |
|------|------|------|
| **频率模式** | 某个事件出现时，AI 去了且收益高 | "黄金怪刷新在等级匹配时，80%情况值得去" |
| **等级模式** | 某个等级段最适合做什么 | "80级后去失落之塔刷材料效率最高" |
| **时间模式** | 某个时间段收益最佳 | "晚上8-10点活动集中，提前留好门票" |

## 七、AI 应用经验的具体逻辑

### 7.1 响应公告时的决策链路（经验增强版）

```
公告消息到达
  ↓
Step 1: AI 公告日志记录
  → 存一条："收到公告: [Lorencia] Golden Invasion!"
  → 如果历史有同样公告的记录 → 查群体经验库 → 获得统计信息
  ↓
Step 2: 规则引擎评估（已有+经验规则）
  → "hunt_golden" 规则匹配 → 但经验库说"这需要等级80+"
  → AI 当前等级 50 → 规则引擎结合经验判断: 去了可能打不过
  ↓
Step 3: 决策
  → 不去（标记: 等级不足）
  → 但决定去侦查一次 → 记录"去了发现怪物等级太高打不动"
  → 这条日志又成为群体的经验
```

### 7.2 公告日志 (AnnouncementLog) 的独特价值

```csharp
/// <summary>
/// 收到的公告记录。让 AI 能"认识"公告模式。
/// </summary>
record AnnouncementLog
{
    string MessageHash;            // 消息指纹（去重）
    string RawMessage;             // 原始文本
    string? ParsedEventType;       // AI 识别出的事件类型
    ushort? ParsedMapId;           // AI 识别出的地图
    short? ParsedMonsterNumber;    // AI 识别出的怪物（如果提到）
    
    DateTime FirstSeen;            // 第一次见到
    int SeenCount;                 // 见过多少次
    DateTime LastSeen;             // 最后一次见
    
    // 经验关联
    List<string> RelatedActionLogIds;  // 关联的行为日志ID
    string? KnownWorth;                // "这个事件值得去" / "不值得"
}
```

多次见到同一格式的公告，AI 可以自己总结出模式：
```
初见:  "[Lorencia] Golden Invasion!"  → 未知事件
第二次: "[Devias] Golden Invasion!"    → 模式: 格式一致，地图名不同
第三次: "[Noria] Golden Invasion!"     → 确认: XXXX Invasion! = 入侵事件
多次后: "入侵事件一般在5分钟后结束"      → 经验: 持续时间约5分钟
```

## 八、关键设计原则

1. **经验是沉淀出来的，不是写死的** — 不预设"黄金怪应该怎么打"，让 AI 自己去试、去记录、去总结
2. **个人经验≠群体经验** — 每个 AI 有自己独特的经历（不同等级、职业、装备），但都汇总到群体库
3. **经验→规则是半自动的** — AI 只生成规则候选（RuleCandidate），高置信度自动写入，低置信度需用户确认
4. **日志追加不覆盖** — `action_logs.json` 只追加写入，不做原地更新，保证历史可追溯
5. **公告日志是认知起点** — 即使 AI 不去打，记下"什么公告出现在什么时间"，长期就能摸清时间规律

────────────                        ────────────
